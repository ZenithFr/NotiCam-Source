# Bug hunt — 2026-10-31

Scope: reviewed the parent repository's Python training/export modules, notebook generator, diagnostics/tests, and sampled Android submodule (`3f15d0c`) camera lifecycle, NPU, and manifest paths. This is a targeted static audit, **not** a claim that every Android/Vulkan path was dynamically verified. The Android application is a separate Git repository: app fixes must be submitted there and its submodule SHA updated separately; editing the checked-out submodule here would not produce a deployable parent-repository fix. No APK was rebuilt or hardware tested.

## 1. Logical issues

**ISSUE #1 — High, silent training on synthetic data (fixed here).** Precondition: training mount or glob is missing. Operation: `train_stage1.py`, `train_stage2.py`, `train_qat.py` previously generated random samples and used the *same dataset* for training and validation. Result: meaningless checkpoints/IoU could be treated as real. Fix: require matching train and validation TFRecords and, for later stages, their preceding checkpoint. Verify: missing paths raise `FileNotFoundError`, not a checkpoint. Side effect: old graph-smoke invocations without data now fail intentionally; use a separate synthetic smoke script if needed.

**ISSUE #2 — High, uncalibrated production export (fixed here).** Precondition: export invoked without weights or calibration data. Operation: `export_int8.py` previously exported initialized weights and calibrated [0, 255] *random* RGB, despite training on [0, 1] real RGB, while allowing float op fallback. Result: invalid input quantization/delegation. Fix: require weights + representative TFRecords in the training range, require integer builtins, and verify before writing the artifact. Verify on a Kaggle/TensorFlow environment: export with a real shard and examine `Interpreter` input quantization, ops, and device delegation. **Not verified here:** the NPU input/output quantization contract of this *new* model; do not deploy solely on the static checks. `train_qat.py` passes its training shard as calibration input.

**ISSUE #3 — Medium, nonportable generator (fixed here).** Precondition: another clone path. Operation: `build_kaggle_notebook.py` wrote to `/home/zenith/Work/auxcam/kaggle` instead of its own directory. Result: writes fail or go to somebody else's checkout. Fix: derive directory from `__file__`. Verify: `python kaggle/build_kaggle_notebook.py` writes alongside script. The committed notebook differs from its generator's current output (including different batch size); do **not** publish regenerated notebook without reviewing those differences.

**ISSUE #4 — High, unauthenticated external capture trigger (upstream app).** Precondition: another installed application can broadcast `com.zenith.auxcam.CAPTURE_STILL`. Operation: `CameraController.kt:283-287` registers `Context.RECEIVER_EXPORTED` with no sender permission. Result: an external app can request photos with `high_quality`/`enable_zsl`, even though the user did not press shutter. Fix upstream: use `RECEIVER_NOT_EXPORTED` for in-app broadcasts, or protect a genuinely external API with a signature-level permission and explicit sender validation. Verify with a separate unprivileged test app (not the privileged `adb shell` UID): its broadcast must not capture.

## 2. State management issues

**STATE_ISSUE #1 — High, disposal races still callbacks (upstream app).** Scenario: leave activity during a still. Current state changes: `CameraController.kt:300-349` shuts down `io`, closes readers, joins only `readerThread`, destroys native engine; `stillThread` started at ~456 is never quit/joined and `matteSegmenter` is not closed. At ~713 `onStillImage` can call `io.execute` after shutdown (rejected task), or processing can overlap `native.destroyEngine`; repeated activity recreations leak still threads. Correction upstream: stop accepting callbacks, close session, drain/join still thread (not from itself), close segmenter, then destroy engine; guard `io.execute` on disposal. Test repeated open/capture/close and watch thread count, rejected executions, MediaStore entries. Do **not** simply wait on the main thread for an unbounded still operation (ANR risk).

**STATE_ISSUE #2 — Medium, partial record shards (partly fixed here).** Scenario: first image corrupt or `shard_size=0`. Old behavior: empty shards or modulo-zero crash; open writer could leak if write failed. Current behavior: shard by *successful* examples, close in `finally`, reject nonpositive size/all-corrupt input. Remaining risk: an interrupted run can leave a partially written shard and older extra shards matching the same glob. Correction: write into a fresh run directory and atomically publish a manifest/rename after completion; don't reuse a prefix for resumed runs without cleanup. Test interruption after first write followed by a shorter rerun.

## 3. Implementation gaps / error propagation

**GAP #1 — High, "QAT" stage is not quantization-aware training.** `train_qat.py:30-63` uses plain Adam and the float model; there are no fake-quant layers or QAT API. Error path: float weights → post-training conversion → expected QAT accuracy is not guaranteed. Implement actual TF-MOT (or equivalent) with supported ops, checkpoint/export conversion, quantization-aware validation, and on-device quality/latency regression. Until then label artifacts PTQ, not QAT.

**GAP #2 — Medium, audit tool cannot validate this checkout reliably.** `kaggle/ml_training/audit.py` hardcodes `/home/zenith/Work/auxcam`, expects an obsolete `build/auxcam_aligned.apk`, and only *warns* if delegation or latency logs are missing. Error path: missing logs → warning → caller sees successful exit. Implement configurable app/build path, explicit APK resolution and fail-closed parsing, then run against the same model SHA deployed to the app.

**GAP #3 — Medium, training metrics and scheduling.** Stage 2 cosine schedule assumes 400 steps/epoch regardless of actual shard size (`train_stage2.py:46`). Per-batch metric averaging overweights the smaller final batch; derive schedule from verified record count and aggregate metrics by sample. Test corpus sizes of 1, `batch_size+1`, and a full epoch.

**GAP #4 — High, app-only device gates still needed.** `CameraController.kt` closes `HardwareBuffer` in `onStillImage` after `native.processStill` but not in a `finally`, so native exceptions leak a buffer; `onPreviewSurfaceCreated` logs failed `initEngine` but still permits session creation. Fix upstream with a `try/finally` for buffer ownership and propagate init failure to state before starting camera. Test forced native-init failure, failed still conversion, then recovery without a process restart.
